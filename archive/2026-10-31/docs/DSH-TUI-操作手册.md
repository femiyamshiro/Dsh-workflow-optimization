# DSH TUI 工作基准操作手册

适用环境：本机 Ubuntu 桌面，DSH **0.2.1-rc.3**、TUI **0.17.0**、OPS **0.4.1**，已采用本地任务看板修订。核对日期：**2026-10-29（Asia/Singapore）**。

本手册以已安装版本的命令与界面实现为准，结合本机基准迁移、模型往返和剪贴板验证记录编写。菜单文字可能随中英文设置变化。插件贡献的命令与面板以当前 `/help`、`/plugin` 和 `/settings` 实际显示为准；不把其他版本的教程当成本机已具备的功能。

## 1. 先会这六件事

| 想做什么 | 入口与操作 |
|---|---|
| 打开工作基准 | 双击桌面“DSH TUI 工作基准”，或在终端运行 `dsh-baseline` |
| 选择旧对话 | 输入 `/agentview`，左侧选工作区，右侧选对话，按 Enter |
| 在当前工作区开始新话题 | 输入 `/new`；原对话仍可恢复 |
| 打开另一个已有项目目录 | 输入 `/workspace open /项目的绝对路径`；会在该目录新建会话 |
| 创建新项目 | 先在文件管理器或终端创建文件夹，再用 `dsh-baseline "/项目路径"` 打开 |
| 找命令与插件面板 | `/help` 看命令，`/panel` 选面板，`/settings` 管理显示与设置 |

**最重要的区别：恢复旧对话用会话列表；换目录并开始新对话用 `/workspace open`。**

## 2. 从哪里启动

### 2.1 桌面快捷方式

双击桌面上的 **DSH TUI 工作基准**。它在终端中打开基准版，初始工作目录是：

```text
${SERVER_PROJECT}
```

快捷方式文件位于：`${SERVER_USER_HOME}/桌面/DSH TUI 工作基准.desktop`。

若桌面仍提示“不受信任的启动器”，对该图标右键，选择“允许启动”。文件已设置可执行并写入信任标记，但实际桌面是否显示图标取决于桌面环境。

### 2.2 在终端启动

```bash
dsh-baseline
```

打开指定项目：

```bash
dsh-baseline "${SERVER_PROJECT}"
```

也可以先进入项目目录：

```bash
cd "/项目的绝对路径"
dsh-baseline
```

恢复上次会话或指定会话：

```bash
dsh-baseline --resume
dsh-baseline --resume 会话ID
```

终端命令中，路径有空格时加双引号。`会话ID` 是 `/status` 显示的 ID，不是对话标题。

### 2.3 几个相似入口

| 命令 | 本机用途 |
|---|---|
| `dsh-baseline` | 日常工作基准，优先使用 |
| `dsh-workflow-tui` | 已指向同一个工作基准 |
| `dsh-tui` | 原普通 TUI 入口，配置与基准不同 |
| `dsh` | 原生 CLI，不能只凭这个名字认定加载了 TUI 基准 |

基准使用 `workbench-tui` profile，默认 **PTC＋OPS＋本地主模型 flash-next-iq3-xxs＋Xhigh**。恢复旧会话可能保留旧会话记录的模型、强度和其他选择，应以当前底栏与 `/status` 为准。

**一次运行一个工作基准实例。** 已有实例占用 43934 时，新入口会退出，不会停止原实例。想在一个基准内管理多条对话，用会话管理器，不要反复开第二个基准。

## 3. 工作区、对话、任务是什么关系

| 名称 | 含义 | 举例 |
|---|---|---|
| 文件夹／项目目录 | 磁盘上真实存在的文件位置 | 一个代码仓库或资料目录 |
| 工作区 Workspace | TUI 对项目目录的登记与展示 | “服务器优化”“网站项目” |
| 对话／会话 Session | 一段独立的消息历史与上下文 | 同一项目里的“排错”“新增功能”两条对话 |
| 工作目录 cwd | 当前工具操作的实际目录 | 可通过 `/status` 查看 |
| 任务卡 Board task | 有提示、执行记录和验收状态的任务 | “修复导出接口” |
| Jobs | 运行中的后台作业 | 某次工具启动的长命令 |
| Agents | 当前任务的子代理或团队成员信息 | 研究、实施等子任务 |

一个工作区可以有很多对话。新建对话不会新建文件夹；给工作区改名也不会重命名磁盘目录。

模型在执行中可能通过工具进入子目录或 Git worktree。此时当前 cwd 会变化，而会话仍归在最初的项目下。找不到文件时，先看 `/status`，不要只看工作区名称。

## 4. 认识主界面

启动后通常先出现落地页：标题／鲸鱼、输入框、继续对话等操作区。直接输入问题即可开始。

进入对话后，主要区域是：

- **消息区**：用户消息、助手答复、工具调用卡片、计划和通知。
- **输入区**：输入消息、斜杠命令、文件引用和附件。
- **参数与状态区**：模型、思考强度、模式、权限、目录、上下文占用等。
- **侧栏**：终端够宽且启用全屏布局时，显示工作区、待办、任务、代理等面板。

模型、思考强度、模式、权限这些参数区域支持相应选择操作；纯键盘使用时，直接调用 `/model`、`/effort`、`/preset`、`/permission` 更明确。

界面太挤时，先扩大终端或减小字体。完整侧栏至少需要约 **93 列可用内容宽度**，外层边距还会占用空间；实践中建议把窗口拉到 110～140 列左右。

## 5. 创建和登记工作区

### 5.1 创建一个全新的项目文件夹

在文件管理器中创建文件夹，或者在**普通终端**执行下面的示例，把路径换成自己的：

```bash
mkdir -p "${SERVER_USER_HOME}/Projects/我的新项目"
dsh-baseline "${SERVER_USER_HOME}/Projects/我的新项目"
```

如果已有基准在运行，先正常退出原基准，或在原基准中用下一节的方法打开这个目录。不要为同一套正式看板同时开两个基准 Host。

**当前会话管理器左栏没有“＋创建文件夹”按钮。** 它主要管理已经登记的目录；从目标目录启动 TUI 会自动登记该工作区。

### 5.2 不退出 TUI，打开一个已有文件夹

在 TUI 输入框输入，例如：

```text
/workspace open ${SERVER_PROJECT}
```

该操作会在目标工作区**新建一个会话**，不会恢复那个目录上次的对话。

斜杠命令不是 Bash：这里的整段路径按参数正文处理，带空格的路径直接写即可，不要照搬终端命令的引号。建议使用绝对路径。

目标目录必须存在且可访问。`/workspace open` 不负责替你创建不存在的文件夹。当前回合运行中可能拒绝切换目录；先等任务结束，或在当前会话按 Ctrl+C 中断后再切换。

### 5.3 给工作区起个好认的名称

切到该工作区后输入：

```text
/workspace rename 服务器优化
```

这只改变工作区显示名称，不会移动文件夹，也不是给当前对话改标题。

## 6. 选择工作区与选择旧对话

### 6.1 最稳定的完整入口：`/agentview`

1. 在输入框输入 `/agentview` 并按 Enter。
2. 按 **←** 把焦点移到左侧工作区栏。
3. 用 **↑／↓** 选择工作区。
4. 按 **→** 进入右侧会话列表。
5. 用 **↑／↓** 选中旧对话，按 **Enter** 打开。

也可以用鼠标操作。点击左栏工作区可能先展开操作菜单；选“编辑／Edit”进入该工作区的会话列表，选“新建”会创建一条新会话。

右侧最上方的“新建会话”是一张操作卡，**不是最近的历史对话**。想续聊时，要选它下面真正的对话行。

### 6.2 `/resume`、`/home` 与侧栏

```text
/resume
/home
```

这两个入口也用于工作区／会话浏览；当分栏开启且工作区面板可用时，它们可能在**右侧工作区面板**打开，而不是铺满屏幕。需要明确打开完整会话管理器时，用 `/agentview`，或点击面板的放大按钮。

本机这版 TUI 的 `/resume` 主要是列表入口。**精确按 ID 恢复，使用终端命令 `dsh-baseline --resume 会话ID`**；不要把 `/resume 会话ID` 当成已验证的直达方式。

### 6.3 搜索会话

在会话管理器里直接输入关键词即可过滤。可匹配标题、标签、目录、分支和模型等字段。

- **←／→**：在工作区栏与会话栏之间切换。
- **↑／↓**：移动选择。
- **Enter**：打开当前会话，或执行当前工作区菜单项。
- **Ctrl+N**：在选定工作区新建会话。
- **Ctrl+L**：刷新列表。
- **Esc**：先清空筛选／关闭菜单，再返回对话。

若左栏消失，通常是窗口过窄；加宽终端再看。若列表为空，先检查筛选词、所选工作区以及界面是否还在加载。

### 6.4 工作区菜单与移除

工作区菜单包含查看／编辑、新建会话、重命名、移除等操作。

“移除工作区”只忘记该目录的登记，不删除项目文件或对话记录；当前正在使用的工作区会被保护。遗留对话可能进入未登记分组。重新从该目录启动或打开目录，可再次登记。

### 6.5 “占用中／OCCUPIED”是什么

表示另一进程持有该会话。不要删除 session.lock 或手工改原生日志来强行打开。回到原终端继续，或正常退出准确的原实例，再刷新列表。

**在管理器里换一条对话，不等于停止原对话的工作。** 对于在同一 TUI 内驻留的 DSH 会话，切换主要改变当前查看对象；任务可能仍继续运行。

## 7. 新建、重命名、清屏与导出对话

| 命令 | 效果与使用时机 |
|---|---|
| `/new` | 在当前工作区开始新会话；原会话保留，可从列表恢复 |
| `/rename 接口排错` | 给当前会话改标题；建议用能识别任务的名称 |
| `/clear` | 清空当前显示的消息投影；不等同于创建新会话，也不能当成可靠的模型上下文重置 |
| `/export` | 将会话导出为 Markdown，文件路径会在界面提示 |
| `/status` | 查看当前会话 ID、目录、模型、运行状态等 |

想换一个完全独立的话题，使用 `/new`。想释放或整理同一任务的上下文，用下一章的 `/compact`，不要依靠 `/clear`。

导出会写入当前工作目录。导出内容可能包含工具参数、结果和思考文本等记录，分享前先检查；不要把“导出”理解成只导出最后一句答案。

DSH 与其他内核的历史管理快捷键不完全一致。会话管理器里 Ctrl+R／Ctrl+D 的改名、删除／归档提示主要属于其他后端的分支，**不要照抄成 DSH 通用操作**。本机 DSH 改名优先使用 `/rename`。

## 8. 输入、换行、补全和引用文件

### 8.1 普通输入

- **Enter**：发送，或在当前菜单确认。
- **Shift+Enter**：换行；终端识别不了时，可试 **Alt+Enter** 或 **Ctrl+J**。
- **↑／↓**：在输入框适当位置浏览历史输入。
- **Ctrl+R**：搜索历史输入；这是输入历史，不是工作区会话管理器。
- **Esc**：关闭当前弹层／撤销当前输入操作；具体以当前提示为准。
- **Tab**：补全命令或选择候选项。
- 输入 **`/`**：查看斜杠命令候选。

### 8.2 引用文件

输入 `@`，从候选文件里选择，再描述你要做什么。例如：

```text
请解释 @src/main.py 的入口逻辑，并指出需要补测试的分支。
```

也支持行范围引用，如 `@src/main.py#L12-40`。相对路径跟随当前工作目录；遇到路径不匹配，先 `/status`。

引用文件是把它加入本次任务上下文，不表示自动同意修改它。只想阅读时，把“只分析，不修改文件”写清楚。

### 8.3 长输入与草稿编辑

- **Ctrl+G**：打开草稿编辑器。
- **Ctrl+Shift+E**：切换编辑器展开形态；具体保存、返回键以编辑器底部提示为准。
- `/vim`：切换输入框的 Vim 编辑模式。启用后 Esc 进入 Normal，`i` 等返回 Insert；并非所有弹窗都变成 Vim 导航。
- **Ctrl+Z**：输入编辑的撤销；不是项目代码回滚。

### 8.4 `!` 命令

输入框支持 `!` 开头的本地 Shell 命令，例如 `!pwd`。这是实际执行命令，会受当前权限与运行环境约束。普通问题直接输入，不必加 `!`；会修改文件、启动服务或安装软件的命令应先核对目标。

## 9. 剪贴板、截图、图片和附件

### 9.1 本机粘贴方法

| 操作 | 用法 |
|---|---|
| 读取系统剪贴板 | **Ctrl+V**，备用 **Alt+V** |
| 由终端粘贴文字 | **Ctrl+Shift+V**；通常不负责把截图转换成图片附件 |
| 文件管理器复制文件后粘贴 | 使用 Ctrl+V，由 TUI 识别文件 URI 列表 |
| 截图后粘贴图片 | 使用 Ctrl+V；按界面提示确认附件与本次消息 |
| 通过路径引用图片 | 使用 `@图片路径`，遵守同样的附件尺寸与格式限制 |

本机已补齐 `wl-paste/wl-copy`、`xclip`、`xsel`，并验证 TUI 原生接口可读取图片。没有覆盖当前剪贴板来做测试。

### 9.2 图片为什么会调整尺寸

过大图片可能由已有 `sharp` 组件缩小或转换格式，界面会提示调整。需要改变动画的图片可能被拒绝，以免静默丢帧；换成静态截图通常更直接。

支持缩略图的终端可以预览图片，并有放大、缩放／平移等操作；不支持图形协议的终端可能只显示文字或附件路径。这不等于附件没有进入输入区。

**能粘贴图片、能在终端预览图片，与模型是否支持看图是三件事。** 模型能力以所选路线声明及实际响应为准。

### 9.3 远程终端的边界

SSH 中的 `wl-paste` 读取的是远端桌面剪贴板，不自动获得你本机的截图。远程文字粘贴通常由终端完成；图片可用文件传输后按路径引用。当前未部署公网浏览器 TUI。

## 10. 选择模型与调整思考强度

### 10.1 模型选择

输入：

```text
/model
```

在模型选择器中选择提供方／模型，按界面提示确认。界面具有提供方分组、模型行和支持的思考强度区域，方向键、Tab 和 Enter 的用途以当前底部提示为准。

选择后核对底栏或 `/status`。切换通常影响**后续请求**，不会重算已经完成的消息，也不代表某个正在生成的请求被热切换。

### 10.2 思考强度

```text
/effort
/effort status
/effort xhigh
```

无参数打开强度选择；具体档位由当前模型声明。选择器的左右移动可能直接应用档位，并非一定要等退出时才保存。

本机基准默认 Xhigh；恢复旧对话会保留记录的强度，因此进入旧会话后仍应看状态。Auto 由已保存选择、配置或模型默认值决定，不等于强制关闭思考。

Xhigh 可能更慢，尤其在工具往返和长上下文下。不要把几秒没输出就判断为失败；可以观察状态、工具卡片与任务信息。当前没有“Xhigh 总比 off 更好”的通用结论。

### 10.3 `/thinking` 不是思考强度

```text
/thinking
```

它主要控制思考文本的**显示**。隐藏思考不等于引擎停止思考；要改实际请求强度，用 `/effort`。

## 11. PTC 预设、模式与权限

### 11.1 确认 PTC

```text
/preset status
/preset
/preset ptc
```

PTC 让模型以代码组合和调度已提供的工具；OPS 是补充文件与文档操作的工具插件。通常直接提出任务，模型自行选工具，不需要用户手写 PTC 程序。

**预设有“空白会话”限制。** 空白会话可以当场换组合；已经开始的会话可能锁定原组合，新选择作为后续新会话的默认。想明确启用 PTC，可先 `/new`，在发送首条任务前 `/preset ptc`，再核对状态。

**Shift+Tab** 可切换会话模式，具体候选取决于当前内核和配置。不要把模式循环、Agent 预设和权限当作同一个设置；确认 PTC 优先使用 `/preset status`。

### 11.2 权限选择

```text
/permission
```

| 常见选项 | 大意 |
|---|---|
| 只读／read-only | 常态下不允许文件修改 |
| 工作区读写／workspace-write | 常态下允许在会话工作区内写入 |
| 完全访问／danger-full-access | 范围更宽，执行前尤其要核对目标 |
| Auto／实验性自动审核 | 额外实验能力，可能有额外确认和成本；不是普通必需设置 |

权限与 PTC 相互独立。底栏显示“完全访问”时，表示当前会话的权限选择，不代表必须如此才能用 PTC。

遇到审批面板，先看命令、路径和影响，再用方向键／Tab 选择、Enter 确认；拒绝时可按界面输入反馈。不要把“允许工具执行”误当作“业务结果已验收”。

## 12. DeepSeek 账号在哪里登录

在 **TUI 输入框**执行：

```text
/auth status
/auth login deepseek-account
```

也可从 `/provider` 的提供方界面选择 DeepSeek 账号登录，或输入 `/auth login` 后按提示选择提供方。

操作顺序：

1. 保持当前 TUI 实例开着。
2. 发起登录，按界面打开授权页面，在浏览器里完成账号登录与授权。
3. 等待 TUI 报告登录成功；它需要本次 Host 的本地回调入口。
4. 用 `/auth status` 查看状态。
5. 用 `/model` 选择 **deepseek-account** 路线对应的模型。

如果浏览器没有自动打开，使用 TUI 本次显示的授权链接；不要把含临时授权信息的整段链接发给别人。远程 SSH 中的浏览器回调涉及端口转发，不能简单假设远端的 127.0.0.1 等于本机。

### 12.1 三种路线不要混淆

| 路线 | 登录或凭据 | 本机默认是否依赖它 |
|---|---|---|
| 本地主模型 femiya-local | 本机已配置的推理服务凭据 | **是当前基准默认路线；不需要 DeepSeek 账号登录** |
| deepseek-account | DeepSeek 浏览器账号授权 | 只有选择这条模型路线才使用 |
| DeepSeek API 提供方 | 对应 API Key | 与浏览器账号授权分开配置 |

登录一个账号不会自动把所有会话切换到它，也不会自动替换本地主模型。

退出某个账号：

```text
/auth logout deepseek-account
```

该命令会移除对应保存的凭据。`/login`、`/logout` 是较通用／历史的凭据入口；针对账号明确使用 `/auth ...`，避免弄错对象。

## 13. 上下文、用量与压缩

| 入口 | 查看／处理什么 |
|---|---|
| `/status` | 模型、ID、目录、工作状态和上下文概况 |
| `/context`／Ctrl+P | 已加载的上下文、文件、工具和相关信息 |
| `/tokens` | 请求、回合、会话与窗口占用等分开统计 |
| `/cost` | 用量与费用估算信息 |
| `/compact` | 对同一任务的旧内容做压缩，释放上下文空间 |
| `/new` | 新任务从独立会话开始 |
| `/recap` | 对近期活动生成简短回顾及建议标题；会调用模型 |

`/compact` 通常需要模型工作，会改变后续使用的上下文表示。压缩中可按界面提示取消，等收尾结束再切会话。它不是项目文件备份，也不保证每个细节都原样保留。

本地推理的界面费用数值不能直接当成电费、机器成本或云账户账单；费用未知或估算应按界面标注理解。

## 14. 回退、分叉和会话树

### 14.1 回退 `/rewind`

输入 `/rewind`，或在适当的空输入状态下双击 Esc，打开回退选择器。选历史消息，阅读确认内容后执行。

默认回退的是**对话**。只有界面实际提供并说明文件恢复方式时，才涉及文件恢复；不要假设对话回到过去，磁盘文件也自动回去了。

运行中的回合不能直接回退。先等结束或停止并等待收尾。回退／恢复文件前，有重要未提交修改时先使用 Git 或自己的备份保留。

### 14.2 分叉 `/fork`

`/fork` 创建当前对话的可恢复副本。原会话与其运行回合保持，副本可从会话列表进入。适合从同一份已知背景试另一条思路。

**分叉会话不等于复制项目目录或创建 Git 分支。** 两条会话可能仍写同一目录，须避免同时改同一文件。

### 14.3 会话家族树 `/tree`

`/tree` 展示回退／分叉形成的会话关系，可浏览、预览，并通过行菜单执行可用操作。树内快捷键以底部提示为准，不要把树里的 Ctrl+B 当成主界面的侧栏切换。

## 15. 运行中追问、停止和后台会话

### 15.1 运行中发送补充要求

运行期间继续输入时，消息可能进入待发送队列。队列、插话、下一回合的区别看当前界面提示，**不要把 Enter 一概理解为立即中断重启**。

输入框可用 Alt+↑ 取回最近的待发送消息进行编辑，具体以队列存在和界面提示为准。

### 15.2 侧问 `/btw`

```text
/btw 这里的 PTC 和普通工具调用有什么区别？
```

适合不想直接改动主任务方向的短问题。可显示在侧问面板，侧栏不可用时使用浮层。侧问仍可能调用模型和占用推理资源，尤其本机只有一个主模型生成槽时，不应把它当成免费并发。

### 15.3 停止当前生成

在主对话按 **Ctrl+C** 打断当前任务，然后等取消／工具收尾结束。停止不撤销已经写入文件、启动服务或完成的外部操作。

### 15.4 暂放当前会话

```text
/bg
```

将当前 DSH 会话放到后台管理，再打开会话管理器。会话行会显示实时状态。停止驻留的后台会话可在管理器选中它后按 **Ctrl+X**；当前正附着的会话用主界面的停止操作。

切换对话可以让工作继续，但**关闭整个 TUI Host 不是后台托管**。本机工作基准不是常驻守护服务。

## 16. 侧栏、插件面板与面板切换

### 16.1 打开与选择面板

```text
/panel
/panel workspace
/panel todo
/panel jobs
/panel agents
/panel info
/panel trajectory
/panel btw
/panel companion
```

无参数打开面板选择器；指定 ID 直接打开相应已启用面板。已注册的插件面板也可出现在选择器里，但“安装插件”不代表它一定贡献 TUI 面板。

| 面板 ID | 界面名称 | 主要内容 |
|---|---|---|
| workspace | 工作区 | 项目与会话导航 |
| todo | 待办 | 当前会话目标与 Todo 进度 |
| jobs | 任务 | 后台作业、输出和停止入口 |
| agents | 代理 | 子代理／团队成员及详细信息 |
| info | 信息 | 当前会话与状态信息 |
| trajectory | 轨迹 | 会话事件与执行轨迹 |
| btw | 侧问 | 与主任务分开的短问答 |
| companion | 伙伴 | 终端伙伴／装饰展示 |

### 16.2 焦点、放大、宽度

- **Ctrl+B**：智能打开／聚焦侧栏；侧栏已聚焦时可收回。
- **Esc**：从面板返回聊天；有的面板会先返回上一级详情。
- 焦点在侧栏时，**←／→** 或 **`[`／`]`** 可切换面板；面板自己的业务按键可能优先处理。
- **Alt+Z** 或 `/panel zoom`：切换面板放大。
- `/panel toggle`：显示／隐藏侧栏。
- `/panel focus`：把焦点放到侧栏。
- 可以拖动分隔线调整宽度；面板聚焦时 `+`／`-` 也可调整。

**在 tmux 内，默认 Ctrl+B 是 tmux 前缀。** 想把 Ctrl+B 传给 TUI，通常先按一次 Ctrl+B，再按一次 Ctrl+B；或使用 `/panel` 命令避开冲突。

### 16.3 启用、隐藏和设置插件面板

输入 `/settings`，在 General／常规页找到侧栏相关设置，检查：

- 是否使用全屏布局而非 inline。
- 侧栏分栏是否开启。
- 已启用面板列表里是否勾选了目标面板。
- 插件是否确实加载并注册了该面板。

设置有多个插件页时，**Tab／Shift+Tab** 切换设置页。这与聊天输入中的 Shift+Tab 模式切换不是同一个场景。

匿名、无法确认稳定组件身份的插件面板，开关可能只在本次运行生效；有稳定身份的面板可保存设置。面板红点／徽标可能表示失败或未读信息，进入面板查看实际内容。

### 16.4 为什么点了没有侧栏

先扩大窗口，退出草稿编辑器的展开状态，确认全屏与侧栏开关。窄屏和 inline 下，有些功能会退回整屏浮层，有些只提示侧栏不可用，不能保证所有面板都有相同回退形式。

本机这个版本没有把 `/panel manage` 作为可靠的侧栏管理命令；管理面板优先使用 `/settings` 的启用列表，不照搬不匹配版本的帮助片段。

## 17. 插件管理、OPS、MCP 和 Skills

### 17.1 插件查看入口

```text
/plugin
/plugin list
/plugin info dsh-ops
/plugin registries
```

分别用于概览、已装插件、特定插件信息和源信息。不同宿主服务可用程度不同，若某项提示服务未加载，不能仅凭命令存在认定它已生效。

高级入口：

| 形式 | 作用 | 是否会改变安装／配置 |
|---|---|---|
| `/plugin check 清单路径` | 检查插件声明，清单通常是 dsh-plugin.json | 以检查报告为准，不等同于安装 |
| `/plugin install 包名或路径` | 安装插件流程 | 会 |
| `/plugin enable 插件名或行ID` | 启用插件／组件 | 会 |
| `/plugin disable 插件名或行ID` | 禁用插件／组件 | 会 |
| `/plugin remove 插件名或行ID` | 移除插件／组件 | 会 |

**我们采用的是固定组合工作基准。** 查看信息可以直接做；安装、启停、移除或升级会改变组合，可能需要重启或重新验证。不要把上游通用教程中的一键升级，当成这个基准的日常维护步骤。

### 17.2 OPS 在哪里用

OPS 主要向模型提供文件读取、发现和文档操作工具，PTC 下可被程序化组合调用。它不是一个必须单独打开的聊天页面，也不必存在 `/ops` 命令。

通常直接描述需求，例如：“读取这三份配置，比较差异，只返回需要修改的项。” 在工具卡片、轨迹和上下文信息里检查实际是否调用了相应工具。

已安装版本的文档能力有格式和预算限制；有文本层读取能力不等于支持 PDF OCR、任意网页搜索或完整文档排版。不要靠一个“OPS 已加载”标签推断所有能力。

### 17.3 MCP

```text
/mcp
```

查看已连接服务、状态和工具信息。支持的连接管理子命令以该界面的补全／说明为准；重连、启停或新增服务可能影响当前任务。

本机记忆、知识库等服务仍遵循各自的数据范围和读写规则。工具可见不代表可以任意写入或搜索全部资料；提出任务时应说明要用的项目、资料范围和目的。

### 17.4 Skills

```text
/skills
```

查看已发现的技能。支持用户调用的技能可出现在 `/` 补全里。技能是工作指导与资源，不等于独立模型或新的文件权限。新增／修改 Skill 之后，不能只凭文件出现就断言现有会话已经加载。

## 18. 任务看板：创建、执行、反馈、验收

### 18.1 看板与其他列表的区别

- **Todo 面板**：当前会话内部的步骤。
- **Jobs 面板**：实际运行的后台作业。
- **任务看板**：可以跨会话保留的任务卡和人工验收流程。

当前本地派生提供 `/board` 命令；它不是内置八面板中的一个。完整图形看板在同一 Host 的辅助 Web 中显示。

### 18.2 常用命令

```text
/board help
/board list
/board new 修复导出功能 | 读取当前项目，修复导出错误，运行相关检查，并说明修改与验证结果。
```

创建会返回任务 ID。然后按需使用：

```text
/board show 任务ID
/board run 任务ID
/board note 任务ID 补充要求或验收标准
/board reject 任务ID 导出为空时仍然报错，请修复并增加回归检查。
/board confirm 任务ID
```

| 命令 | 含义 |
|---|---|
| list | 列出未归档卡片 |
| new | 创建卡片，绑定当前工作目录与当时的权限；竖线左边是标题、右边是执行要求 |
| show | 查看卡片、执行记录、相关会话和运行／验收信息 |
| run | 提交实际执行，会调用模型或工具 |
| note | 追加说明；已在执行的请求不保证立刻吸收新备注 |
| reject | 在可打回的状态提出反馈，之后按流程再次执行 |
| confirm | 人工确认可验收的卡片，不是替代项目检查 |

可用完整任务 ID，或至少 6 个字符且唯一的前缀。拿不准时用完整 ID。显示“已受理”只说明动作被接收，仍要用 show 查看后续状态。

### 18.3 一个完整流程

1. 先确认当前目录与权限。
2. 创建卡片，写清产物和验收要求。
3. `/board run ID` 开始执行。
4. 用 show 查看是否完成、是否还存在活跃 Jobs。
5. 卡片进入 **review／待验收** 后，实际检查产物和测试结果。
6. 合格才 confirm；不合格则 reject 并写明问题。

**review 不等于已完成，更不等于验收通过。** 自动结算成功只进入待验收。

### 18.4 图形看板与定时任务

基准 TUI 开着时，同一 Host 提供：

```text
http://127.0.0.1:43934
```

进入原生 Web 页面后找“任务看板”。若要求认证，使用本次 Host 提供的原生入口，不能假设它继承另一个 Web 实例的登录状态。

图形看板包含卡片状态、备注、验收、归档和支持的调度选项。任务可分一次性、定时重复、交互式；交互式卡不能随意当定时自动执行使用。定时任务是否触发取决于 Host 存活、规则启用及界面支持，关闭整个 TUI 后不保证继续执行。

**该地址是本机辅助页面，不是现有公网 Web，也不是公网 TUI。** 不要为了访问它直接向公网裸露端口。当前公网 Web 保持原入口，本轮任务板并未发布到公网。

## 19. 目标、计划、Todo、后台 Jobs 和子代理

### 19.1 长任务目标 `/goal`

当你确实要持续推进一个长任务时，可使用：

```text
/goal 完成当前项目的导出模块修复并通过相关测试
/goal
/goal pause
/goal resume
/goal edit 修改后的明确目标
/goal clear
```

设置／恢复目标可能驱动后续模型轮次，不是纯粹写一个标题。`/goal clear` 清的是目标，不会自动清空 Todo，也不撤销已完成的文件操作。

### 19.2 计划与 Todo

模型可在会话里维护可见的计划／Todo。当前任务步骤可在底部或 todo 面板查看；Ctrl+Q 用于折叠运行中的待办，或隐藏空闲时的目标／待办显示。

若当前 `/` 列表提供 `/plan`，按它返回的状态与操作提示使用；计划命令来自宿主／插件，不在不同版本间假定同一套子命令。

### 19.3 Jobs 面板

输入 `/jobs` 或 `/panel jobs` 查看。常见状态包括 running、stopping、completed、failed、killed。

面板可浏览输出，`e` 展开／收起，按界面要求连续两次 `k` 停止选中的作业。停止作业不是撤销已经发生的副作用。需要向当前聊天补充某个作业结果时，使用面板实际提供的“附加到聊天”操作。

### 19.4 子代理与团队

- `/agents`：查看当前会话的子代理信息。
- Ctrl+A：打开代理仪表板；在输入框／编辑器场景可能优先执行行首等编辑操作。
- `/panel agents`：以侧栏查看代理及详情。
- `/team`：查看已运行 Team 服务的状态；**不等于启用团队服务**。

Team 及其他扩展是否可用取决于 profile 是否加载对应组件。当前基准未凭一个菜单入口宣称完整 Team 工作流已验收。多会话、多代理也不代表本地主模型具备相同数量的并发生成槽。

## 20. 设置、主题、布局、通知和显示

```text
/settings
/theme
/lang zh
/activity
/color
```

### 20.1 `/settings` 的常用项目

- 语言、主题、显示布局、落地页。
- 侧栏开关、已启用面板和宽度相关设置。
- 思考文本显示与默认推理强度。
- 快捷键重映射。
- 工具输出、动画、任务通知等显示偏好。
- 有独立设置页的插件配置。

设置页中 Tab／Shift+Tab 切页，方向键／Enter 操作当前项，Esc 返回。保存与即时生效方式看当前界面提示；并非所有配置都能热加载。

TUI 自身设置保存在 `~/.dsh-tui/settings.json`，可能被其他 TUI profile／内核共用。因此改主题、快捷键或侧栏偏好，不一定只影响基准入口。

### 20.2 常用显示操作

- `/theme`：选择主题；`/lang zh` 切中文。
- `/color`：设置当前会话的强调色。
- `/activity`：切换工作指示动画。
- **Ctrl+O**：切换较详细的消息／工具输出显示。
- **Ctrl+E**：查看更完整消息范围；编辑输入时可能由编辑动作优先处理。
- **Ctrl+T** 或 `/trace`：打开轨迹。
- **Ctrl+L**：重绘；会话列表中则是刷新列表。

### 20.3 通知

在 `/settings` 的对话相关设置中配置任务通知。一般可选择未聚焦时通知、总是通知或关闭，以及 auto、终端协议或响铃等方式。

通知依赖终端本身是否支持与允许。tmux 场景需要透传和焦点事件支持；当前已提供专用配置文件：

```text
${SERVER_LOCAL_SHARE}/dsh-tui-support/dsh.tmux.conf
```

本机没有为了这些设置覆盖你的全局 `.tmux.conf`。

## 21. 用 tmux 保持终端会话

适合不想因为关闭终端窗口而丢掉运行中的 TUI。它解决终端会话保持，不是公网浏览器终端，也不能阻止主机休眠或关机。

本机已安装 tmux。首次使用可在普通终端运行：

```bash
tmux -f "${SERVER_LOCAL_SHARE}/dsh-tui-support/dsh.tmux.conf" new-session -s dsh-workbench
```

进入 tmux 后再运行：

```bash
dsh-baseline "${SERVER_PROJECT}"
```

暂时离开而保留运行：先按 **Ctrl+B**，松开后按 **D**。回来时：

```bash
tmux attach-session -t dsh-workbench
```

先检查是否已有同名会话或基准实例，不要在另一个 tmux 窗口又启动一套基准。tmux 的 `-f` 配置在相应服务器首次启动时加载；已有默认服务器时不保证这次命令重新载入所有选项。

真正结束工作时，先在 TUI `/exit`，然后退出空闲 tmux shell；不要对不确定归属的 tmux 服务器执行 kill-server。

## 22. 导入其他工具的历史与更换内核

### 22.1 导入历史

`/migrate` 可列出支持的历史来源，并按提示选择导入。高级形式例如：

```text
/migrate codex --dry-run
```

“干跑／dry-run”是预览，真正导入会在 DSH 侧写入会话。来源页签中选中其他工具的会话并 Enter，可能执行“导入并打开”，不是只读预览。

导入历史与换内核是两件事。导入后作为 DSH 会话继续，并不等于恢复了来源工具的全部运行状态、权限和功能。不要为了日常找会话就批量导入所有历史。

### 22.2 更换内核

`/kernel`、`/dsh`、`/codex`、`/claude` 用于选择／切换不同执行内核，可能重启、创建新会话或安装所需 SDK。

本手册主体是 **DSH 基准内核**。看到“Claude 未安装”不代表 TUI 的剪贴板、文件工具或本地主模型缺失；也不代表需要立即安装它。更换内核后，模型、会话历史、权限、命令和账号语义可能变化，不能照搬 DSH 的所有步骤。

## 23. 退出、重启、诊断和版本管理

| 入口 | 用途与注意点 |
|---|---|
| `/exit`、`/quit`、`/q` | 正常退出整个 TUI |
| Ctrl+D | 输入为空等适当状态下退出；优先用 `/exit` 表达意图 |
| `/doctor` | 显示环境诊断；不等同于跑完所有功能验收 |
| `/config` | 查看配置来源信息；分享输出前检查是否包含不应公开的信息 |
| `/reload` | 重新读取支持的偏好文件；不等于全部插件或原则热加载 |
| `/restart` | 上游提供的重启并恢复入口；固定基准日常优先退出后重新运行 dsh-baseline |
| `/setup` | 重跑首次使用引导；已有凭据和工作配置时无需为了继续工作反复运行 |
| `/terminal-setup` | 查看当前终端与粘贴相关提示 |
| `/tips`、`/help`、`?` | 查用法与快捷键 |

查看本机基准版本，在普通终端运行：

```bash
dsh-baseline --version
```

### 23.1 固定基准的升级限制

`/update`、普通入口的 update、插件安装和启停，属于改动软件组合。我们当前保留 RC3 组合，没有把 alpha 直接投入工作。要升级先做兼容性验证，不在工作中随手更新。

基准入口会检查固定组件，遇到版本／受保护工作流文件变化时可能拒绝启动。不要为了消除拒绝而删检查或强行换包。

### 23.2 启动失败进入安全菜单

当前上游安全菜单的“重试／救援”不保证保留 `workbench-tui` profile。**退出该菜单，修复具体原因后重新运行 `dsh-baseline`。** 不要把进入普通／救援 TUI 当成基准修复成功。

## 24. 常见问题速查

| 现象 | 先做什么 |
|---|---|
| 不知道当前在哪个目录 | `/status` 查看 cwd |
| 找不到旧对话 | `/agentview`，检查工作区、筛选词、来源页签，Ctrl+L 刷新 |
| `/resume` 只打开侧栏 | 这是分栏路由；改用 `/agentview` 打开完整管理器 |
| 换工作区后历史空白 | `/workspace open` 创建的是新会话；在会话列表选择旧对话 |
| 没有新建工作区按钮 | 先创建目录，再从该目录启动／打开 |
| 窗口里没有左栏或侧栏 | 加宽终端、减小字体；检查全屏与侧栏设置 |
| 43934 已占用 | 已有基准／历史工作流实例；使用原实例或正常退出它，不杀不明进程 |
| 会话 OCCUPIED | 另一进程持有；回原终端或正常退出准确的持有者 |
| Ctrl+B 没反应 | 检查是否被 tmux 截获、面板是否启用、窗口是否够宽 |
| Ctrl+V 提示工具不可用 | 本机已补工具；确认从当前桌面启动、PATH 有 ~/.local/bin；SSH 剪贴板另论 |

| 隐藏思考后仍然慢 | `/thinking` 是显示设置；查看 `/effort`、上下文与实际运行状态 |
| 切了 PTC 但当前旧会话没变 | 旧会话可能锁定预设；在新空白会话选择并确认 |
| 任务看板 review | 待人工验收，先检查产物再 confirm |

| `账号已登录` 但仍用本地模型 | 登录不自动改模型；去 `/model` 选账号路线 |
| 登录后网页回调失败 | 保持发起登录的 TUI 活着；确认浏览器能到达该 Host 的本地回调 |
| Team 或插件页显示不可用 | 入口存在不等于相应服务已加载；看 `/plugin` 与实际提示 |
| 界面乱码／残留 | Ctrl+L 重绘，确认 UTF-8、字体与终端尺寸 |
| 关闭窗口后任务没了 | 普通 TUI 随 Host 退出；需要保持时先在 tmux 内启动 |

## 26. 一套完整的日常工作流程

### 情况 A：继续昨天的项目

1. 双击桌面基准快捷方式。
2. `/agentview` → 选择工作区 → 选择昨天的对话。
3. `/status` 确认目录、模型、强度；需要时 `/preset status`。
4. 写清今天要继续的内容和验收标准。
5. 看工具卡、Todo、Jobs 或看板状态判断实际进展。
6. 检查产物与测试，必要时在看板人工验收。
7. 用 `/rename` 给对话起清楚的标题；正常 `/exit`。

### 情况 B：在已有项目开一个独立新任务

1. `/agentview` 选择项目工作区。
2. 选“新建会话”，或按 Ctrl+N。
3. 首条任务前确认 PTC、模型和权限。
4. 提交任务；与旧对话相互独立，但仍可能写同一目录。

### 情况 C：开始全新项目

1. 文件管理器创建目录。
2. 在已有基准输入 `/workspace open /新目录绝对路径`；或退出后从该目录启动。
3. `/workspace rename 新项目名称`。
4. `/new` 仅在你还需要另外一条新对话时使用，不必把它当作创建文件夹步骤。
5. 需要项目规则时 `/init` 创建缺失的 AGENTS.md，再核对内容；已有规则不要覆盖。
6. 描述目标、允许操作的范围和验收方式，开始工作。
